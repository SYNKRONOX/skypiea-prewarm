Vocabulary mapping

The predictor knows the airline support vocabulary. Skye's refund is counted as a cancellation (reservation_cancel) and added baggage as a modification (reservation_modify); customer lookup and verification are user_lookup. Unknown tools are sent as "other": no prediction.

Truth check

After each Skye reply, simple rules look for "done" claims (changed, cancelled, refunded, baggage added) and compare them with the writes that really succeeded in that turn. It can miss unusual phrasings. Skye's text is never edited.

How Skypiea works

  1. Every tool Skye uses runs in its own container that sleeps when idle (scale to zero), so the first call has to wait for it to start.
  2. While the LLM is still thinking, Skypiea's predictor guesses the next tool from the names and timing of the calls so far, and starts that container early.
  3. If the guess is right, the call finds a warm container. The Normal column shows the same calls without prediction.

Cost: starting containers early keeps them warm longer, which costs idle time. The summary shows both the time saved and the extra warm time; time saved can be negative.

Setup: Tool containers are real and cold-start for real; the airline data is a mock database inside the console; the predictor sees only tool names and timing.
