How to read it:
- **Labels:** kind cold starts (laptop: a lower bound), local 8B model (llama3.1:8b, Ollama,
  temperature 0), SYNTHETIC profile `prd` (shipped bundle lgbm-prd-a7642d0, image
  `a7642d03dd10`), 10 sessions per cell, real LLM think times. The model's `/decide` counter
  confirmed which predictor served each run: 0 requests in the stub runs, 32 and 34 in the
  predictive runs.
- Sessions ran **one after another** and were short (a 10-session cell took 43 to 135 s). So
  under keep-alive and predictive, a pod started for one session often served the next one.
  The low cold rates of keep-alive and predictive reflect this; they are not per-session
  prediction quality. Under scale-to-zero, B is only 32% cold, likely for a similar reason (not verified): the
  controller's 5 s minimum dwell and purge delay keep a pod up for a few seconds, and B's
  calls arrive back to back.
- **The hideable fraction is small.** The LLM think gap has median 1,354 ms and p90 2,938 ms.
  Cached AWS cold starts are 2,572 to 3,791 ms. Only 7.9% of calls (cached) and 0.5%
  (uncached) have a think gap that is long enough on its own. In 25 of 30 B sessions the
  model sent several tool calls in one reply, so those calls reached the gateway with no gap.
- **Graph following:** B 25/30, A 12/30. In A the 8B model often asked the customer to
  confirm, or repeated a tool: 18/30 sessions repeated a tool, and 19/30 ended `no_tool_call`
  after 2 nudges.
- No CI is given: the cells are too small. Nothing was tuned, and no cell was rerun. Every
  number comes from the run files.

## What failed, and why

1. **The kind API returned `EOF` at the start** (Docker Desktop's port forward went stale after
   a resume). Fix: `docker restart skypiea-control-plane skypiea-worker`.
2. **Grafana was evicted in a loop** (740 dead pods): Grafana 13 downloads about 540 MB of
   plugins into its 512 Mi emptyDir. Fix in the chart: `GF_PLUGINS_PREINSTALL_DISABLED=true`
   (`charts/skypiea/templates/monitoring.yaml`). I deleted the evicted pods.
3. **The first fresh-clone `make demo` failed** at cluster creation: Docker Desktop returned
   `ports are not available ... /forwards/expose ... 500` for every published port. `docker
   desktop restart` from WSL failed; the Windows CLI (`.../DockerDesktop/resources/bin/docker.exe
   desktop restart`) worked. The second attempt passed. This restarted Docker Desktop once; the
   only container running then was `kind-registry`, and it kept its images. Documented in
   DEMO.md, Troubleshooting.
4. **llama3.1:8b often answers in text** ("can you confirm...?") instead of calling a tool.
   Before any measured run (from a 1-session smoke test), I added a fixed simulated-user reply,
   at most 2 per session; it is counted in `nudges`. The client still raises a clear
   `NoToolCallError`, and the session ends `no_tool_call` after the second nudge.
5. **This worktree's old `.venv` lacked `hypothesis`**, so 1 test failed until `make setup`
   synced it to the lock. The fresh clone was green from the start.

## Decisions made without asking (conservative defaults)

- **Demo bundle from the samples.** A fresh clone has no `data/processed`, so `demo/prepare.py`
  builds a SYNTHETIC `prd` bundle and the sessions from `data/samples`. The demo predictor image
  holds only that bundle (profiles coding and support fail loudly). The live runs used the
  **shipped** prd bundle instead (`a7642d03dd10`, from the local registry).
- **Demo gaps:** think gaps capped at 6 s and tool time at 2 s. Scenario A, 8 sessions, 4 at
  once. Labelled "functional demo, not results".
- **No new dependency:** the LLM client uses `httpx`, which is already locked. So
  `requirements*.txt` and the lock are unchanged, and `pip check` passes.
- No gateway or controller code changed, so the image tag stays `96a0735`. The only platform
  change is the Grafana env in the chart.
- Live sessions run one at a time, because one local GPU model would queue concurrent
  requests and inflate the think times.
- `make agent-demo` writes to `.demo/` (git-ignored). Only `make agent-live` writes to
  `results/`.

## Risks

- The live table is small (10 sessions per cell), runs on kind, uses a SYNTHETIC profile and
  one local 8B model. Sessions run back to back share warm pods. Do not compare it with the
  AWS tables.
- Docker Desktop on WSL broke twice tonight. Before a live presentation, run the port check
  in DEMO.md and keep `docs/demo_transcript.log` as a backup.
- Image builds on a machine with **no** Docker cache were not timed.
- `make demo` rebuilds the demo predictor image after every commit (the bundle records the
  commit). This takes about 10 s with the pip layer cached.
